Navigation and overlays

Where a person is and where they can go, and what opens over the page: navigation lists, menus, dialogs and tooltips. Where each sits on the page is the product's to say.

Navigation list

Destinations with an optional avatar or glyph, and a label that truncates while keeping the end padding. The current destination has aria-current="page". Padding above and below accommodates a full avatar; a small one makes a denser row. Use links for destinations and buttons for actions, with their native keyboard behaviour.

.nav-list.nav-item.nav-item__label aria-current

Folding navigation section

A native disclosure groups destinations under a heading with an even hover box. The summary works with Enter or Space and hides the links from the tab order when closed. Long headings use the same label as an item. Nested items use the smaller control height and font, with a quiet tree guide aligned under the heading's chevron. The guide is decorative; this remains ordinary link navigation, with no tree roles or extra keyboard rules.

Nested navigation items

A smaller step in height and type separates a section's destinations from a top-level item. A vertical guide and short ticks show the group. Avatars and counts retain their size; labels truncate before them. The guide follows the inline direction and the surface's border token.

Navigation heading with an action

A shared heading row with two independent targets. The action is a sibling of the native disclosure, outside its summary, and remains available when the section closes. Hover or keyboard focus covers the row; focusing a destination below it does not highlight the heading.

Navigation heading with several actions

Group one or more trailing actions outside the disclosure. Their actual width reserves space beside the heading, while the destinations still span the section. Hover and keyboard focus cover the heading row, not its destinations. The arrow opens the full list; the chevron only folds this section.

Person menu header

A non-interactive identity above a menu's items: avatar, name and a secondary line for a handle and short role, followed by a separator. Both lines truncate while the avatar keeps its size. Arrow keys visit only the items below. The name can also label the menu for assistive technology.

Menu destination with an action

A destination fills the row beside a separate icon action. Each has the menu's hover and keyboard focus. In a menu element, both participate in arrow-key navigation and send the same select event; disabled targets are skipped. Name icon-only actions for assistive technology, and wrap long text in a label.
